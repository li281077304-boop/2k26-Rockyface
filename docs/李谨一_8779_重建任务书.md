## 0. 最重要的先读：头模格式已破解（这改变了可行性）

NBA 2K26 的 `hihead.SCNE` **是 JSON 明文**，不是二进制。里面明确声明了顶点流。
经实测验证（`mods_work/RobbieAvila8779/png8779.iff`）：

| 项 | 值 |
|---|---|
| 顶点数 | **24,484**（SCNE 内 `"LodVerts": 24484`）|
| 坐标流 | `VertexBuffer.f2fce607cb4c3b42.bin`，**Stride 12 = float32×3 纯坐标** |
| 坐标校验 | 解析出的 min/max 与 SCNE 声明的 Min/Max **完全吻合**：`[-78.05, -103.63, -12.88] ~ [78.05, 81.14, 27.47]` |
| 索引流 | `IndexBuffer.c829179a1bc03cf2.bin`，**uint16，235,236 个索引（78,412 三角形）**，最大值 24,483 = 顶点数−1 ✓ |
| **UV 流** | `VertexBuffer.7c6afba5d91ba744.bin`，**Stride 16，偏移 4–7，uint16 UNORM / 65535**。程序化穷举 + UV wireframe 验证后唯一命中。脸上 UV 在中央偏上椭圆区域（U≈0.4–0.6, V≈0.05–0.30） |
| 权重流 | `MatrixWeightsBuffer.313dc1adc1fb35a9.bin`，157,960 B |
| 顶点流2 前段 | `VertexBuffer.7c6afba5` 偏移 0–3 / 8–15，打包法线/切线 |
| 顶点流4 | `VertexBuffer.1ba830a661e6c481.bin`，Stride 4，1,119,336 B（不能按 24484 整除 → 可能用于 LOD1+ 或共享给其他网格）|
| Morph | **稀疏 R8_UINT 增量**，`Scale: 0.015625`（1/64），SCNE 内按名字声明（如 `brow_innerDown_L`）|

**结论：头模可以直接 numpy 读写；UV 已确认并定位脸部子区域。**

## 3. 头模：landmark 约束拟合（不再 Y/Z 区域缩放）

坐标流已可直接读写（见第 0 节）。建议流程：

1. MediaPipe Face Mesh / dlib 提取多张照片的 landmark（眼角、鼻翼、鼻尖、嘴角、下巴、脸缘）
2. 需要一张 3D↔照片的对应关系。两条可行路：
   - 渲染 24,484 顶点云的正面/侧面投影，人工/自动标定 8779 mesh 上的同名 landmark
   - 用 `IndexBuffer` 重建三角网格后做最近邻/轮廓匹配
3. Thin-Plate Spline / RBF 对坐标数组做连续形变
4. **保持顶点数、顺序、UV、skin weights 不变**，只写回 `f2fce607cb4c3b42.bin`

**必须同时更新 SCNE 里的包围盒**（`Min` / `Max` / `Center` / `Radius`），否则可能被裁剪。

形变目标（成年骨架上的幼态脸）：脸长明显缩短、儿童式圆润脸颊、下颌角弱、
下巴短圆、鼻梁低、鼻尖小不前突、眉骨弱、眼眶浅、眼裂按照片、耳位按照片。

注意：原生 8779 的 358 个 Morph 是稀疏增量（R8_UINT / Scale 0.015625），
它们叠加在**原坐标**之上。改了基座后表情可能轻微偏移，属于可接受代价；
如果表情崩坏，考虑把 Morph 的 delta 一并按同样形变场重映射。

## 4. face_color 整张重建（禁止中央矩形补丁）

v0.1 / v0.2 的失败根因：照片按**矩形裁剪**投影到 UV，四边硬边切在脸上
（实测改动矩形 x 431–1597 / y 517–1070），嘴、下巴、两颊根本没被改到。

新版要求：
1. 以**原生 8779 UV** 为坐标

3. 多视角 multiband / Poisson blending
4. 最外围平滑过渡到 8779 原生 scalp / ears / neck
5. **输出前生成 UV seam heatmap**，重点检查：鼻翼、眼角、嘴角、下颌、耳前、发际线

**968dd067 的嘴是露齿笑，嘴部区域不得从此图取样。**

## 11. Morph 处理（关键风险点）

`最终顶点 = BaseMesh + MorphDelta` 这条公式一旦成立，把基础脸从成年改成儿童后，
眉毛、嘴角、眨眼等 Morph 是为**原生 8779 成年脸**制作的，会叠加在新基座上。
静态编辑球员界面可能正常，比赛中做表情可能嘴裂、眼皮错位。

**拆分方案：**
- **v0.3a：只验证静态基础头模。** 不动 Morph，只把基础头模形变到儿童脸。
  进游戏看静态外观。OK → 进 v0.3b。
- **v0.3b：验证 Morph。** 关键表情：眨眼、张嘴、抬眉、张嘴笑、向左右张嘴。
  如果表情崩坏，要么把 Morph 的 delta 按相同形变场重映射（取原始坐标在新坐标
  中的差值，按 RBF 形变场变换），要么只保留形态最少的 Morph 子集。
- v0.3a/b 都通过才进入 Round 2（纹理）。

**禁止**一开始就同时重算所有 Morph。一次性改太多变量，无法定位回归。

## 12. 头模几何流程（不能用 X/Y/Z 比例缩放）

> 严禁对整张脸按 X/Y/Z 比例缩放，否则鼻子、脸颊、嘴会像是不同人的。

正确流程：

```
8779 原生位置 (24484 × 3 float32)
  ↓
从多张照片提取 landmark（MediaPipe Face Mesh / dlib）
  ↓
在原生 8779 mesh 上对应同名 landmark（人工或最近邻匹配）
  ↓
几十到几百个 anchor 构造目标位置
  ↓
RBF / Laplacian / ARAP 连续形变
  ↓
输出 OBJ 静态预览 (rocky_target_v01.obj)
  ↓
人眼检查（脸长是否缩短、鼻子是否塌、下巴是否怪、左右是否对称、耳位是否合理）
  ↓
几何通过 → 写回 VertexBuffer
```

## 15. UV 解码参考脚本（已就绪）

`mods_work/face_preview/find_uv.py`：
- 读取 SCNE 声明的所有 VertexStream
- 对 (buffer, offset, encoding) 穷举：f32x2 / f16x2 / unorm16x2 / snorm16x2 /
  unorm8x2 / snorm8x2 / r10g10b10a2 / r11g11b10
- 评分：UV 边长 vs 3D 边长对数相关性（杀手判据，真实展开 ≥ 0.6，乱解 ≤ 0.2）
       + in_range + occupancy + 非退化三角形比例
- 渲染前 6 名候选为 wireframe

**结果：UV = VertexBuffer.7c6afba5d91ba744.bin，stride 16，offset 4，uint16 UNORM/65535**
